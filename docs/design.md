# 동기화 설계

## 경계

Canvas 연결, 파일 동기화, 명령행을 나눴습니다. `canvas.py`는 권한이 있는 파일 메타데이터와 내용을 가져오고, `sync.py`는 `Material`과 내용을 읽는 함수만 받습니다. 네트워크를 사용하지 않는 데모와 테스트도 같은 동기화 코어를 호출합니다.

개인 학기나 학교 계정을 코드에 넣지 않습니다. 강좌 ID와 저장용 이름은 사용자 설정에서 받고, 저장 위치는 명령행에서 지정합니다. 교재 생성, 전사 보정, 참가자 관리와 브라우저 프로젝트 편집은 이 패키지의 범위에 포함하지 않습니다.

## 상태와 파일 내용

원격 주소가 같아도 내용은 바뀔 수 있고, 다운로드 이력이 있어도 로컬 파일이 없어질 수 있습니다. 원격 본문과 로컬 파일의 해시를 함께 확인해야 변경과 손상을 구분할 수 있습니다. 이 버전은 매 실행에서 본문을 다시 가져옵니다. 전송량 절감보다 현재 내용의 확인을 우선한 선택입니다.

파일은 내용 해시가 포함된 이름으로 저장하고 이전 버전을 보존합니다. 현재본은 상태 파일과 JSON 결과에서 찾습니다. 상태 저장 전에 프로세스가 중단되면 참조되지 않는 파일이 남을 수 있지만, 이전 현재본을 새 내용으로 덮어쓰지는 않습니다. 전원 손실까지 포함하는 여러 파일의 완전한 트랜잭션은 보장하지 않습니다.

## 실패를 구분하는 방법

- 파일 가져오기 실패는 해당 항목에 기록하고 다른 항목을 계속 처리합니다.
- 전체 목록을 확보하지 못하면 불완전한 목록을 완전한 수집 결과로 보고하지 않습니다.
- 상태 파일이 손상됐으면 새 상태로 조용히 초기화하지 않습니다.
- 동시 실행은 잠금으로 차단합니다. 잠금 파일이 남았다면 해당 작업이 종료됐는지 확인한 뒤 처리해야 합니다.
- 원격에서 사라진 파일을 자동 삭제하지 않습니다. 일시적인 권한 변경과 실제 삭제를 구분할 근거가 충분하지 않기 때문입니다.

## 검증 범위

테스트는 합성 자료로 개정, 손상, 실패와 재실행을 확인합니다. Canvas 어댑터 테스트는 가상의 API 응답을 사용합니다. 새 가상환경에 wheel을 설치한 뒤 데모를 실행해 작업 폴더나 개발환경에 숨은 의존성이 없는지도 확인합니다.

CI에서 테스트를 통과해도 실제 LMS의 로그인 정책, 페이지 구성과 파일 서버가 모두 호환된다고 단정할 수 없습니다. 브라우저 프로필은 개인 데이터이고, 사용자가 내려받은 파일 내용까지 공개 가능한지 자동 판정하지 않습니다.
